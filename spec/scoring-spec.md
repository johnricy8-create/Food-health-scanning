# 评分算法规格 v0.1.0

> 目标：0–100 分，越高越健康。纯规则、可复现、无大模型参与。
> 所有数字都在 `config/params.json`，本文只解释"为什么"。

---

## 1. 输入

```jsonc
{
  "name": "红烧牛肉方便面",
  "category": "方便食品",        // 决定是否走饮料阈值
  "unit": "100g",
  "ingredients": "小麦粉、棕榈油、食用盐、…",   // 保持包装上的顺序
  "nutrition": {                // 中国标签的"1+4"
    "energyKj": 1900, "proteinG": 9, "fatG": 20, "carbG": 58, "sodiumMg": 1800
  }
}
```

`category` 属于 `beverageCategories`（饮料/饮品）时才使用饮料阈值表。
牛奶、豆浆虽然按 100ml 卖，但走普通食品表 —— 这是 Nutri-Score 的官方做法，否则纯牛奶会被按饮料的严格能量阈值判成 D。

---

## 2. 缺失营养素估算（最容易出错的一步）

国标只强制标"1+4"，**糖和饱和脂肪绝大多数产品不标**，而这两个恰恰是评分最关键的输入。

### 2.1 糖

优先用标签值。没标则：

1. 找第一个**产生热量**的糖源（排除赤藓糖醇等糖醇、低聚糖）。
2. 按它在配料表里的位置分档取"碳水里糖的占比"：

   | 糖源位置 | 占比 |
   |---|---|
   | 第 1–2 位 | 0.75 |
   | 第 3–4 位 | 0.45 |
   | 第 5–7 位 | 0.25 |
   | 第 8 位以后 | 0.10 |

3. 两个修正：
   - 前 4 位里有淀粉类主料（小麦粉/淀粉/大米/马铃薯…）→ 占比 × 0.35（碳水主要来自淀粉，不能算成糖）
   - 饮料 → 占比 × 1.2（上限 0.95）
4. 找不到任何糖源时给自然基线：乳制品 ≈ 碳水×0.95（上限 5g，乳糖）；纯果汁 ≈ 碳水×0.9；其他 ≈ min(碳水×0.05, 2g)。

> 举例：火腿肠碳水 8g、白砂糖在第 6 位、前面有淀粉 → 糖 ≈ 0.7g。方便面碳水 58g、白砂糖第 6 位、主料小麦粉 → 糖 ≈ 5g。

### 2.2 饱和脂肪

优先用标签值。没标则 `脂肪 × 饱和比例`，比例取命中的脂肪来源规则里的最大值：

| 脂肪来源 | 饱和比例 |
|---|---|
| 代可可脂/起酥油/人造奶油/植脂末/氢化油 | 0.80 |
| 棕榈油/椰子油/黄油/奶油/动物油/生牛乳 | 0.65 |
| 坚果籽类 | 0.12 |
| 大豆、燕麦 | 0.15 |
| 植物油（菜籽/葵花/大豆/玉米/橄榄…） | 0.25 |
| 未识别 | 0.35 |

后三条带 `dominantOnly` 约束：该原料必须出现在**前 3 位**才生效。否则"大豆蛋白"会被当成脂肪来源，把火腿肠的饱和脂肪算成 2.85g（实际约 7g）。

### 2.3 膳食纤维

没标时按主料推断（燕麦/全麦 6g、豆类 4g、坚果 5g），同样要求出现在前 3 位，否则记 0。

### 2.4 能量

没标时按 `蛋白×17 + 脂肪×37 + 碳水×17`（kJ/g）计算。

**能量交叉校验**：标签标示能量 vs 按三大营养素计算的能量，偏差 > 20% 时判定"OCR 可能读错"，把置信度降为低，并在 UI 上提示用户核对。这一条是抓识别错误最便宜的手段。

## 3. 营养维度（权重 60%）

用 **Nutri-Score 2021** 做底座 —— 国际公开算法，比自己拍脑袋定义的阈值更有公信力，也不怕被质疑。

**负分（各 0–10）**：能量、糖、饱和脂肪、钠，按阈值表打分（`points = 严格大于几个阈值`）。
**正分**：蛋白质（0–5）、膳食纤维（0–5）、果蔬豆类占比（0/1/2/5）。

```
final = neg − (fv + protein + fiber)
特殊情况：neg ≥ 11 且果蔬分满格时，蛋白质不计入   ← 防止用蛋白粉"洗白"
final ∈ [−15, +40]，越小越好
```

等级：A ≤ −1 · B 0–2 · C 3–10 · D 11–18 · E ≥ 19

然后分段线性映射到 0–100：

| final | −15 | −1 | 2 | 10 | 18 | 40 |
|---|---|---|---|---|---|---|
| 营养分 | 100 | 90 | 76 | 50 | 18 | 0 |

**果蔬豆类占比**：中国标签不标，只能按位置估 —— 单一原料 100%、第 1 位 80%、前 3 位 40%、更靠后 5%。

## 4. 加工程度（权重 20%）

NOVA 分类，但只能靠配料表反推：

| 条件 | NOVA | 分数 |
|---|---|---|
| 超加工标志成分 ≥ 2 种 | 4 | 35 |
| 超加工标志成分 1 种 | 4 | 35 |
| 无标志成分但有食品添加剂 | 3 | 65 |
| 无添加剂但有糖/盐/油/醋 | 3 | 65 |
| 无添加剂、≤2 种原料 | 1 | 100 |
| 其他 | 2 | 88 |

"超加工标志成分" = 植脂末/代可可脂/起酥油/麦芽糊精/分离蛋白等工业原料，**或**功能为防腐/着色/甜味/增味/乳化/增稠/香精/膨松/抗结/护色/漂白/稳定/水分保持的添加剂。

凝固剂（豆腐的氯化镁）、酸度调节剂（柠檬酸）、营养强化剂不算标志物 —— 否则一块豆腐会被判成超加工。

---

## 5. 添加剂（权重 20%）

每种添加剂按 tier 扣分：`low 6 / medium 14 / high 30`。

**同功能类别最多累计 2 个**（重的优先）。避免"三种色素直接扣到 0 分"这种失真。

tier 划分依据：
- **high**：亚硝酸盐、TBHQ/BHA/BHT、糖精钠、甜蜜素、脱氢乙酸钠（GB 2760-2024 已限用）、含铝膨松剂、二氧化钛（欧盟已禁）、已禁用的溴酸钾/过氧化苯甲酰
- **medium**：山梨酸钾、苯甲酸钠、阿斯巴甜/安赛蜜/三氯蔗糖、合成色素、焦糖色、磷酸盐、二氧化硫
- **low**：柠檬酸、碳酸氢钠、各类胶体、乳化剂、天然色素、糖醇、天然甜味剂、味精、香精

## 6. 隐藏信号（不再是独立维度）

原"隐形风险"维度已取消——它和营养、添加剂高度重叠，单独列出来只会让用户困惑。检测逻辑保留，扣分直接计入对应维度：

| 命中 | 扣分 | 计入 |
|---|---|---|
| 反式脂肪来源（氢化油/植脂末/代可可脂/起酥油/人造奶油） | −10 | 营养 |
| 游离糖来源（果葡糖浆/玉米糖浆/浓缩果汁/麦芽糊精） | −8 | 营养 |
| 含糖饮料 | −7 | 营养 |
| 多路含钠叠加（味精 + 呈味核苷酸 + 盐 同时出现） | −12 | 添加剂 |

"白砂糖"不算游离糖——它是明示糖，已在营养维度扣过。致敏原只提示不扣分：过敏不是健康问题。

扣完的维度分下限为 0。

## 7. 总分合成

```
mean       = Σ wᵢ·dimᵢ                            w = 0.60 / 0.20 / 0.20
shortBoard = Σ wᵢ · max(0, 65 − dimᵢ) × 0.5        ← 短板惩罚
shortBoard = min(shortBoard, 12)                    ← 必须封顶
raw        = mean − shortBoard
total      = round( min(raw, ceiling[nutriGrade]) )  ← 营养等级天花板
```

短板惩罚为什么要封顶：三维模型里营养占 60%，一个营养分很低的产品光这一项就能扣掉二十多分，再叠加另外两维会变成负数，最后所有差产品都挤在 0 分，失去区分度。封顶 12 分既保留"某一维拖后腿"的警示作用，又不至于淹没均值。

天花板：A 100 / B 95 / C 80 / D 45 / E 25。

理由：营养是 E 的产品（比如方便面），即使配料表干净、没有反式脂肪，也不该拿到高分。反过来，配料表花的零糖饮料不该因为"营养分高"就冲进 A。

显示等级：≥85 A / ≥70 B / ≥55 C / ≥40 D / 其余 E。

## 7.1 食用建议与能量换算

分数下方给三条建议，由 `buildAdvice()` 纯规则生成，只描述份量、搭配、场景，不做健康结论：

- **一次吃多少**：按 `params.servingSize` 查品类份量，换算成"吃一次多少 kcal、占每日参考多少"。
- **怎么搭配**：按钠 > 600mg / 糖 > 15g / 纤维偏低 / 蛋白偏低 依次命中，饮料单独一套规则。
- **什么时候吃**：按能量密度、是否含糖饮料、蛋白与糖的比例分档。

能量参考值：每日 2000 kcal / 8400 kJ（中国 NRV 取整值）。

```
无糖豆浆 96 · 纯燕麦 96 · 北豆腐 90 · 全麦吐司 87 · 纯牛奶 86 · 混合坚果 83

```

排序基本符合直觉。已知待讨论的点：

| # | 问题 | 现象 | 候选解 |
|---|---|---|---|
| 1 | **B 档仍然偏少**（22 个里 2 个：混合坚果 83、无糖气泡水 70） | 分数集中在两端，中间断层 | 收紧 `nutritionMapping.anchors` 的 C 档，或抬高 `lowThreshold` |
| 2 | 无糖豆浆(96) ≈ 纯燕麦(96) | 豆浆蛋白质只有 3g，靠"零负分"拿了 A | 提高蛋白质的区分度，或给"低蛋白"加一个下限 |
| 3 | 零糖可乐 60 | 营养维度 85 分拉高了总分 | 调大添加剂权重（`labelSensitive` 预设下已降到 58） |
| 4 | 沙拉酱 19、儿童饼干 13 偏严厉 | 营养分被压到 15 以下 | 检查 Nutri-Score 对"高脂低糖"产品的处理是否符合预期 |
| 5 | `data/samples.json` 是示意值 | 北豆腐能量校验不通过就暴露了 | 换成真实拍摄样本后再校准 |
| 6 | 置信度只反映"糖"的估算 | 饱和脂肪估算没有体现 | 按"估算误差对总分的影响"加权 |
| 7 | 22 分处出现四个并列 | 可乐 / 火腿肠 / 巧克力棒 / 果汁饮料 都是 22 | 需要真实样本再判断是真同分还是示意值太接近 |
